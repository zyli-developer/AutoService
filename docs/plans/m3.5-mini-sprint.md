### 1.4 Dream engine LLM real-wire (backend) — **promoted 2026-04-22**

**Problem.** Today no Dream path in production actually speaks to an LLM:

- **Per-tenant** (`cinnox` etc.): [`dream_agent.run_dream`](../../autoservice/dream_agent.py#L1117-L1134) requires an explicit `llm_send` callable; the production caller [`api_routes._spawn_dream_run_with_run_id`](../../autoservice/api_routes.py#L776) doesn't supply one — every trigger raises `RuntimeError: run_dream requires an explicit llm_send callable until cc_pool exposes a tool-use surface (T3B.5)`.
- **Master** (`_master`): [`master_dream_agent.run_platform_dream`](../../autoservice/master_dream_agent.py#L51) is a skeleton — emits one static proposal with fabricated evidence. Module contains no `llm_send` / `anthropic` / `tool_use` references; `Tokens 入/出` on every master run is `0 / 0`.

A dev-only stub (`DREAM_DEV_STUB=1`) was shipped on 2026-04-22 ([api_routes.py `_run_dev_stub_dream`](../../autoservice/api_routes.py)) that emits three seed draft proposals after a 3s sleep so the admin-portal Dream UI is exercisable for demo / video capture. It is **not** a product capability — it is a fixture.

**D5 unblocks:** the actual learning behaviour the Dream engine was designed for (soul-prompt iteration, signal-driven proposals, CSAT feedback loop) — none of which can operate without an LLM call.

| M3.5 task | Backend scope | Description |
|---|---|---|
| **D5** 🟡 Dream LLM real-wire | `autoservice/cc_pool.py` + `autoservice/dream_agent.py` + `autoservice/master_dream_agent.py` + `autoservice/api_routes.py` | Land **T3B.5** (cc_pool tool-use surface) + **T4S.4b** (signal-driven per-tenant + master LLM loop). Default the production trigger path to a real Anthropic-backed closure; retain `DREAM_DEV_STUB` as an offline-dev fallback only. |

**D5 scope breakdown**:

1. **`cc_pool` tool-use surface (T3B.5 core).** Expose `client.call_with_tools(system, messages, tools) -> Message` on acquired Dream role clients. Implementation hint: Dream loop is JSON-in/JSON-out (tools are `emit_proposal` / `kb_search` / `list_souls`), no bash/file subprocess needed — can be a thin Anthropic SDK wrapper bound to the acquired client's key, not a full CC tool-use delegation.
2. **`dream_agent` default `llm_send`.** Remove the `RuntimeError` guard at [dream_agent.py:1117-1134](../../autoservice/dream_agent.py#L1117-L1134). When `llm_send is None`, build a closure from the acquired pool client. Tests continue to inject mocks via the existing seam — no signature change.
3. **`master_dream_agent` T4S.4b finish.** Replace the static `emit_proposal` call at [master_dream_agent.py:102-121](../../autoservice/master_dream_agent.py#L102-L121) with a real tool-loop using the same `_run_agent_loop` helper and cross-tenant signals already gathered by `gather_platform_signals`.
4. **`api_routes` wiring.** Drop the `DREAM_DEV_STUB` branch from the default production path in `_run_and_mark`. Keep the env gate so a `DREAM_DEV_STUB=1` run still skips the LLM (useful for CI / offline dev). Document in `CLAUDE.md § Dev Auth Bypass` neighbourhood.
5. **Tests.**
   - Unit: VCR-recorded Anthropic responses for deterministic `run_dream` + `run_platform_dream` coverage (no network at `pytest` time).
   - Integration: 1 live-API test per agent, gated on `ANTHROPIC_API_KEY` presence (`@pytest.mark.live`); skipped by default, opt-in via `pytest -m live`.
   - Regression: all 102 existing `tests/dream_agent/` + `tests/dream_runs/` + `tests/dream/` stay green.

**CON-04 red-line retention.** All proposal writes continue to flow through `emit_proposal` (no `status` kwarg, hardcoded `'draft'`). D5 does not introduce a new write path. The 5-layer defence (signature lock, string hardcode, value rejection, import cone, AST guardrail T4S.8) remains unaltered. **Yellow flag** — requires code-reviewer subagent review before merge (matches M3 T2S.1 / T2S.4 / T2S.5 / T2S.8 pattern).

**Estimate**: 8-12h human / ~2-3h AI (matches M3 backend 4× speedup).

**Dependencies**: none within M3.5 (`DREAM_DEV_STUB` remains a safe fallback during D5 land).

**Gate criteria**:
- Trigger `cinnox` via `/api/dream/trigger` without `DREAM_DEV_STUB` set → row closes `completed` with non-zero `tokens_in` / `tokens_out`, emitted proposal's `title` does **not** start with `[dev stub]`.
- Trigger `_master` → `run_platform_dream` calls the LLM (evidenced by non-zero tokens and non-templated title).
- `pytest tests/dream_agent tests/dream_runs tests/dream tests/api/test_dream_api.py` fully green (mock + VCR; live tests opt-in).
- Code-reviewer subagent APPROVED verdict.

**Risks**:
- **API cost at CI** — mitigated by `@pytest.mark.live` default-skip; opt-in via make target.
- **First live run on cinnox surfaces soul-prompt issues** — budget 1-2h for prompt iteration on `plugins/cinnox/skills/*/customer_soul.md`.
- **cc_pool blast radius** — `call_with_tools` is a new surface; mitigate by scoping to Dream role only (customer / operator / triage paths unchanged).
