# AutoService · IM 底座能力需求 Checklist

> 版本：v1.0 · 2026-04-14
> 配套：`AutoService-PRD.md` / `AutoService-UserStories.md` / `autoservice-full-journey.html`

---

## 0. 使用说明

**目的**：为 AutoService 选型或自建"商户侧 IM 底座"提供一份平台中立的能力清单。IM 平台方或架构决策者可**逐项打勾**，判断候选方案是否满足 AutoService 的功能与非功能要求。

**如何使用**：
- ☐ 未满足 · ☑ 原生满足 · ◐ 部分满足（需应用层封装） · ✗ 不适用
- 每项都标注了**验收方式**（How to verify），便于 spike / PoC 阶段验证
- 分层结构：**基础能力 → 进阶能力（分场景） → 非功能性要求**；基础层是**门槛**，进阶层按业务 Epic 勾选

**范围边界**：本 checklist 只覆盖**商户侧 IM**（管理群 + Agent 分队频道）。面向 C 端的独立站浮动按钮 / PSTN / 20+ 语种客户渠道**不在本清单范围**，由 AutoService `web/` + 外部通道承担。

## 1. 基础功能 Checklist（Must-Have · 任何候选方案必须满足）

> 这一层是**门槛**：任何一条未满足都意味着该 IM 方案无法承载 AutoService 商户侧能力。

### 1.1 群组与成员管理

| ID | 能力要求 | 验收方式 | ☐ |
|---|---|---|---|
| B-CHAT-1 | 通过 API 以编程方式创建群/频道 | 调用 create API 成功返回 channel_id | ☐ |
| B-CHAT-2 | Bot/机器人身份可作为成员加入群 | Bot 入群后能收发消息，客户端显示为正常成员 | ☐ |
| B-CHAT-3 | 支持多群并行（单租户下 ≥ 50 个频道） | 压测创建 50+ 频道无限额阻塞 | ☐ |
| B-CHAT-4 | 群成员进出事件可订阅 | 邀请/踢出成员后 2s 内收到事件回调 | ☐ |
| B-CHAT-5 | 群成员列表可查询 | List API 返回完整 member 列表含角色 | ☐ |

### 1.2 基础消息能力

| ID | 能力要求 | 验收方式 | ☐ |
|---|---|---|---|
| B-MSG-1 | 发送文本消息，UTF-8 全支持（≥ 20 种语言） | 发送中英日韩阿拉伯泰 emoji 混合消息无乱码 | ☐ |
| B-MSG-2 | 消息事件可订阅（接收客户发来的消息） | 订阅 message_received 事件，500ms 内收到回调 | ☐ |
| B-MSG-3 | @mention 机制（@ 人 / @ Bot / @ 全体） | @ 事件可被 Bot 识别并单独处理 | ☐ |
| B-MSG-4 | 消息附带 message_id，可被后续操作引用 | 返回稳定 ID 可用于 update/delete/reply | ☐ |
| B-MSG-5 | 富文本 / Markdown 支持（至少：粗体、列表、链接、代码块） | 渲染符合 Markdown 规范 | ☐ |
| B-MSG-6 | 文件附件上传与下载（PDF、CSV、图片） | 单文件 ≥ 10 MB，类型白名单覆盖常见格式 | ☐ |
| B-MSG-7 | 未读徽章由客户端原生维护 | 客户端频道列表显示未读数，无需应用层实现 | ☐ |

### 1.3 Bot / 开放平台基础

| ID | 能力要求 | 验收方式 | ☐ |
|---|---|---|---|
| B-BOT-1 | 提供官方 Python SDK（AutoService 核心栈） | PyPI 可装，有维护，近 6 月有提交 | ☐ |
| B-BOT-2 | 提供官方 TypeScript/Node SDK（AutoService 前端栈） | npm 可装，类型定义完整 | ☐ |
| B-BOT-3 | 事件推送支持 HTTP Webhook **或** 长连接（WebSocket/SSE） | 二选一即可；长连接优先（穿透代理/防火墙） | ☐ |
| B-BOT-4 | 认证机制标准化（App ID + Secret / OAuth / Token） | 可自动刷新，token 生命周期文档清晰 | ☐ |
| B-BOT-5 | 提供沙箱 / 测试环境 | 独立租户可用于 CI/E2E 测试 | ☐ |
| B-BOT-6 | 速率限制文档公开、可查询当前配额 | 文档列出 QPS/QPM，或 API 响应含 rate limit header | ☐ |

**基础层通过标准**：B-CHAT 和 B-MSG 全部 ☑，B-BOT 至少 5/6 ☑。

## 2. 进阶功能 Checklist A · 商户注册与自助上线

> **对应第一幕 · Act A**：商户 ≤ 2 小时完成从注册到开单的自助流程。
> **挑战**：权限授权零门槛、管理群自动就绪、非技术商户可理解。

| ID | 能力要求 | 验收方式 | ☐ |
|---|---|---|---|
| A1-1 | **一键多权限勾选授权**：管理员一次勾选 ≤ 4 项权限即完成全量授权 | 接入 Wizard 无二次跳转，授权时长 ≤ 60s | ☐ |
| A1-2 | **应用商店式安装**：商户从应用商店一键安装，无需提交工单/等待审批 | 安装→可用 ≤ 60s，无人工介入 | ☐ |
| A1-3 | **权限分层**：区分"上线最小集"与"增强功能集"，基础集免审批 | 文档列出最小权限清单，基础集开箱即用 | ☐ |
| A1-4 | **自动建群 + 自动拉人**：应用安装后自动创建管理群并邀请管理员、Bot | 无需管理员手动建群 | ☐ |
| A1-5 | **文件上传接收**：商户在群内上传产品目录 PDF / 历史对话 CSV,Bot 可下载 | 上传事件可订阅,附件 API 可下载原文件 | ☐ |
| A1-6 | **多租户隔离**：每个商户独立 workspace/tenant,数据物理隔离 | 跨租户 API 调用返回 403,日志审计可按租户过滤 | ☐ |
| A1-7 | **商店应用多租户模式**：一份应用代码服务 N 个商户 | 支持 per-tenant access token / 授权流 | ☐ |
| A1-8 | **应用 Icon/名称/描述可品牌化** | 商户看到的是 "AutoService",不是开发者原名 | ☐ |
| A1-9 | **非技术用户可理解的授权文案** | 权限说明非开发者术语,面向"老陈"级用户可读 | ☐ |

**通过标准**：A1-1, A1-2, A1-4, A1-6, A1-7 必须 ☑（这五条决定 ≤2h SLA 能否兑现）。

## 3. 进阶功能 Checklist B · 日常运营 · 实时对话

> **对应第二幕 · Act B**：Agent 与 C 端客户实时对话,人工客服在 IM 侧监管、接管、协作。
> **挑战**:1 人工:N Agent 的分队模式、流式体验、Copilot / 角色翻转。

### 3.1 分队频道与对话卡片

| ID | 能力要求 | 验收方式 | ☐ |
|---|---|---|---|
| B1-1 | **Agent 分队频道**：每个人工客服拥有专属频道，其下挂多个 Agent 会话 | 建模方式可以是"1 频道 + thread / 子话题"或"N 子频道",只要语义成立 | ☐ |
| B1-2 | **频道内未读徽章**：不同对话的未读状态独立显示 | 客户端未读数按对话粒度、而非频道粒度展示（或能以 thread 粒度展示） | ☐ |

### 3.2 流式卡片与占位续写

| ID | 能力要求 | 验收方式 | ☐ |
|---|---|---|---|
| B2-1 | **互动卡片**：支持 button / select / input 组件 | 卡片 DSL 文档化，渲染一致（桌面+移动） | ☐ |
| B2-2 | **卡片流式更新**：已发送卡片可被 patch，客户端无闪烁更新 | patch 后 < 500ms 客户端可见更新，无重弹通知 | ☐ |
| B2-3 | **卡片刷新频率**：单卡片 ≥ 5 次/秒，单应用聚合 ≥ 50 次/秒 | 压测验证,附速率限额文档 | ☐ |
| B2-4 | **占位+续写消息**：先发 1s 占位 → 5-15s 后续写同一条消息 | 客户端无闪烁、无二次通知、无新消息条目 | ☐ |
| B2-5 | **流式文本/卡片 diff 更新**：仅更新变化字段,非全量重绘 | patch API 支持 partial update | ☐ |

### 3.3 监管窗 / Copilot 模式 / 副驾驶侧栏

| ID | 能力要求 | 验收方式 | ☐ |
|---|---|---|---|
| B3-1 | **子话题/Thread 机制**：主消息下可挂子对话,形成可折叠讨论 | 支持 reply_in_thread/parent_id 字段 | ☐ |
| B3-2 | **Thread 事件可独立订阅**：thread 内消息、thread 生命周期（创建/归档/删除） | 事件类型文档列出 | ☐ |
| B3-3 | **Thread 内消息速率独立计算**：不与主消息共用配额（或配额足够大） | 限额文档或压测验证 | ☐ |
| B3-4 | **替代方案：嵌入 Web 视图**（Thread 不满足时的 Plan B） | 支持卡片按钮跳转应用内 H5 + JS-SDK 获取会话身份 | ☐ |
| B3-5 | **Copilot 模式可见性控制**：监管内容只对商户可见,C 端不感知 | 权限边界清晰,无跨边泄漏风险 | ☐ |

### 3.4 斜杠命令与回调

| ID | 能力要求 | 验收方式 | ☐ |
|---|---|---|---|
| B4-1 | **斜杠命令注册**：`/status` `/dispatch` `/review` `/hijack` `/rollback` 等 | 菜单化注册优于纯文本解析 | ☐ |
| B4-2 | **命令参数解析**：支持参数、选项、自动补全提示 | 命令 DSL 可声明必填/可选参数 | ☐ |
| B4-3 | **卡片按钮回调**：用户点击 ✓/✎/✗ 返回明确事件 | action_id + payload 可携带业务上下文 | ☐ |
| B4-4 | **Agent 主动 @人工 求助** | @ 事件可被 Bot 发出,人工客户端有推送通知 | ☐ |

### 3.5 运营告警

| ID | 能力要求 | 验收方式 | ☐ |
|---|---|---|---|
| B5-1 | **主动推送消息到指定群**：SLA 告警推送到管理群 | 无需用户触发,Bot 可随时 push | ☐ |
| B5-2 | **消息优先级/通知等级** | 高优告警可触发强通知,低优静默 | ☐ |
| B5-3 | **卡片式仪表盘**：指标、趋势、一键动作按钮 | Card 渲染表格/数字/mini chart | ☐ |

**通过标准**：B2-2, B2-4, B3-1（或 B3-4）, B4-3 必须 ☑——这四条是 Epic 2 的技术底线。

## 4. 进阶功能 Checklist C · 闲时学习 · Agent 改进

> **对应第三幕 · Act C**：Dream Engine 每夜跑学习循环,商户管理员在管理群内审批提案、灰度发布。
> **挑战**:审批卡片体验、规则版本追溯、灰度状态可视化。

| ID | 能力要求 | 验收方式 | ☐ |
|---|---|---|---|
| C1-1 | **审批卡片**：提案展示 + ✓通过/✎修改/✗驳回 按钮 | B2-1 通过即可,此条是其应用场景 | ☐ |
| C1-2 | **卡片状态持久化**：审批后卡片保留"已处理"终态 | patch 后历史消息中仍可看到最终状态 | ☐ |
| C1-3 | **@Bot 自然语言对话**：管理员 @Dream Engine 谈配置,Bot 多轮澄清 | 支持多轮上下文 (由 AutoService 后端维护,IM 侧只需可靠收发) | ☐ |
| C1-4 | **历史消息可检索**：按关键词/时间/发送者 查询群历史 | Search API 可用,或消息持久化可从外部查询 | ☐ |
| C1-5 | **消息不可篡改/可审计**：`/rules edit` 每次修改留痕 | IM 消息不可删后无痕（或删除事件可订阅） | ☐ |
| C1-6 | **灰度通知渐进推送**：5% → 25% → 100% 每阶段自动推送状态卡片 | 基于 B5-1 主动推送能力 | ☐ |
| C1-7 | **夜间低峰不打扰**：消息不在夜间触发客户端强通知 | 通知等级可按规则静默 | ☐ |
| C1-8 | **管理群成员变更事件**：客服离职时 Agent 分队可自动重分配 | B-CHAT-4 已覆盖,此条是其应用场景 | ☐ |

**通过标准**：C1-1, C1-2, C1-5, C1-6 必须 ☑。

## 5. 非功能性要求 Checklist（跨所有场景）

> 这一层不属于"功能",但决定运维成本、合规性、可扩展性。架构决策时需同等对待。

### 5.1 运维与可观测

| ID | 能力要求 | 验收方式 | ☐ |
|---|---|---|---|
| N1-1 | 开发者后台提供应用调用日志 | 可按时间、API、状态码过滤 | ☐ |
| N1-2 | 提供应用配置审计日志（权限变更、Bot 配置） | 管理员维度可回溯 | ☐ |
| N1-3 | 支持应用版本管理与灰度发布 | 与 Dream Engine 灰度策略兼容 | ☐ |
| N1-4 | 事件投递有 at-least-once 语义 + 幂等 ID | 消费端可据 event_id 去重 | ☐ |
| N1-5 | SDK 支持自动重试 + 断线重连 | 官方 SDK 内置或文档提供示例 | ☐ |

### 5.2 合规与数据

| ID | 能力要求 | 验收方式 | ☐ |
|---|---|---|---|
| N2-1 | 数据存储地区可选（中国境内 / 海外） | 满足跨境商户合规 | ☐ |
| N2-2 | 消息/文件传输全程 TLS | 加密等级文档化 | ☐ |
| N2-3 | 提供数据导出能力（退出时带走历史） | Export API 或导出工具 | ☐ |
| N2-4 | 敏感权限有独立说明文档,便于安全审计 | 权限粒度清晰 | ☐ |

### 5.3 性能与限额

| ID | 能力要求 | 验收方式 | ☐ |
|---|---|---|---|
| N3-1 | 消息 API 单应用 QPS ≥ 100 | 文档或压测确认 | ☐ |
| N3-2 | 事件投递 P99 延迟 ≤ 2s | 监控或文档 | ☐ |
| N3-3 | 单群成员上限 ≥ 500 | 建群 API 文档 | ☐ |
| N3-4 | 单文件上传上限 ≥ 50 MB | 文档 | ☐ |
| N3-5 | 限额超限有清晰错误码与重试建议 | API error 规范 | ☐ |

### 5.4 地区与部署

| ID | 能力要求 | 验收方式 | ☐ |
|---|---|---|---|
| N4-1 | 同一套代码可服务中国大陆 + 海外商户（或提供迁移路径） | SDK 支持多 region,或 API 兼容层 | ☐ |
| N4-2 | 跨地区身份可映射（同一商户内部 user 可绑定双端账号） | 中长期规划项,短期可仅支持单地区 | ☐ |

## 7. 使用建议

1. **选型阶段**：把本 checklist 发给每个候选平台方（或自建方案 PM）填写,配合官方文档链接作为证据
2. **PoC 阶段**：对标 ☐ 和 ◐ 条目逐一做 spike,把"文档说满足"转成"实测满足"
3. **架构决策**：
   - 第 1 层任一 ☐ → 该平台**不可用**
   - 第 2-4 层按业务优先级取舍;如果仅承接 Epic 1(商户注册),只要通过第 1 层 + 第 2 层即可
   - 第 5 层打分低但功能强,可进入,但需在实施阶段评估运维/合规风险
4. **长期维护**：本 checklist 应随 PRD 版本滚动更新,每个新 User Story 都应反向校验是否产生新条目
